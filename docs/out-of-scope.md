# 本期不做清单（Out of Scope）

> **文档版本**：v1.0.0
> **最后更新**：2026-05-10
>
> 本文档明确声明 MVP 阶段**不做**的事情。
> 这是范围防御，避免"顺便加一下"式的范围蔓延。

---

## ⚠️ 使用原则

1. 此清单里的事情，**任何人都不能在 MVP 阶段提出来做**
2. 如果确实需要提前做，必须：
   - 在评审会上集体讨论
   - 评估对 MVP 时间线的影响
   - 从清单中移除并加入 `requirements.md`
3. 如果 MVP 上线后要做，走 v2 迭代计划

## 🛡️ 范围防御检查清单

开发过程中，每当有人提出新需求，先问：

- [ ] 此需求在 `requirements.md` 中吗？
  - 是 → 继续评估
  - 否 → 是否在 `out-of-scope.md`？
    - 是 → 明确拒绝：已声明本期不做
    - 否 → 加入 `open-questions.md` 等评审
- [ ] 此需求是否阻塞 MVP 上线？
  - 是 → 纳入 MVP，同步更新文档
  - 否 → 加入 v2 列表
- [ ] 此需求是否只是"看起来简单"？
  - 评估真实工时
  - 评估对现有模块的冲击
  - 评估测试成本
