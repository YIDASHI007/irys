# 业务规则清单（Business Rules）

> **文档版本**：v1.0.0
> **最后更新**：2026-05-10
>
> 所有重要业务规则集中在此，按 `BR-XXX` 编号管理。

## 一、账号与权限（BR-1XX）

### BR-101 · 用户手机号全局唯一
每个手机号只能对应一个 `User`。不同租户（未来多租户）允许重复，单租户内不允许。

### BR-102 · 首次登录强制改密
新创建的账号，首次登录后必须在 30 分钟内修改密码。

### BR-103 · 密码强度
- 长度 ≥ 8
- 必须包含字母、数字、特殊字符中至少 2 种
- 不能与历史近 3 次密码相同

### BR-104 · 登录失败锁定
连续失败 5 次锁定 15 分钟。超管可手动解锁。

### BR-105 · JWT 过期策略
- Access Token：2 小时
- Refresh Token：7 天
- 修改密码后所有 Token 失效

### BR-106 · 角色分配唯一性
一个用户可以拥有多个角色。多角色时权限取并集，数据范围取最大。

### BR-107 · 数据权限继承
上级部门的管理者自动拥有下级部门的数据权限。

### BR-108 · 账号停用规则
账号 `DISABLED` 后：
- 无法登录
- 名下线索/客户保留但只读
- 30 天内可恢复，超过 30 天数据归档

## 二、CRM / 线索 / 客户（BR-2XX）

### BR-201 · 线索手机号去重
同一手机号在系统中只能存在一条 `status != INVALID` 的线索。重复提交时：
- 后台录入：提示"已存在，是否合并"
- 小程序留资：默默更新最后提交时间，不创建新记录

### BR-202 · 线索状态机
```
NEW → CONTACTED → INTENTIONAL → CONVERTED
  │       │            │
  └───────┴────────────┴──→ INVALID
```
- 只能按箭头方向流转
- `INVALID` 和 `CONVERTED` 为终态
- 驳回需要填写原因

### BR-203 · 线索分配规则
**手动分配**：运营/销售主管可手动指定负责人。
**自动分配**：按渠道/城市/品牌配置规则，匹配的线索自动分配给候选销售中：
- 当前持有线索数最少者
- 同数时按上次分配时间最早者

### BR-204 · 公海线索回收
- 默认 15 天未跟进 → 自动回公海
- 可在系统设置中调整
- 跟进后重置计时

### BR-205 · 单销售线索上限
- 默认每销售持有线索上限 200 条
- 达到上限后，新线索自动进公海
- 可在系统设置中调整

### BR-206 · 抢单防刷
- 每销售每日最多抢公海线索 20 条
- 并发抢单使用乐观锁

### BR-207 · 跟进记录不可删除
- 创建后 1 小时内可编辑
- 超时后只读
- 永不物理删除

### BR-208 · 线索转客户条件
线索状态变为 `CONVERTED` 需满足：
- 至少有 1 条跟进记录
- 必须由销售主动触发（AI 只能提建议）
- 触发后自动创建 `Customer` 记录

### BR-209 · 商家转介绍记账
`source = REFERRAL` 时必须填写 `referrerId`（User 或 Customer）。未来用于佣金计算。

## 三、招商项目 / 品牌（BR-3XX）

### BR-301 · 项目状态流转
```
DRAFT → RECRUITING ⇄ PAUSED
           │
           └────→ CLOSED（终态）
```

### BR-302 · 项目关联限制
一个招商项目只关联一个品牌。如需多品牌共用政策，复制项目。

### BR-303 · 项目到期自动关闭
项目 `endDate` 到期后定时任务自动改为 `CLOSED`。

### BR-304 · 资料包访问控制
```
PUBLIC           所有人可下载（含未登录）
AFTER_LEAD       提交过线索后可下载
APPROVED_ONLY    审核通过的意向客户可下载
```
每次下载写入审计日志。

### BR-305 · 小程序展示过滤
小程序只展示满足以下条件的项目：
- `status = RECRUITING`
- 未到 `endDate`
- `visible = true`
- 当前用户所在城市在 `targetRegions` 内（如配置了）

## 四、加盟商（BR-4XX）

### BR-401 · 加盟商创建前置
加盟商记录只能在以下场景创建：
- 合同签订时自动创建
- 运营主管手工创建（需审批）

**不允许**加盟商自行注册（MVP 阶段）。

### BR-402 · 加盟商状态流转
```
ACTIVE ⇄ SUSPENDED → TERMINATED（终态）
```

### BR-403 · 加盟商等级手工评定
MVP 阶段由运营主管手工评定，不做自动规则。变更需审批且通知加盟商。

### BR-404 · 加盟商账号隔离
加盟商账号只能看到：
- 自己名下的门店、合同、账单、通知
- 公共内容（品牌、公告）

**绝对不能看到**：
- 其他加盟商
- 平台内部员工信息
- 平台内部数据

## 五、门店 / 门店数据（BR-5XX）

### BR-501 · 门店生命周期
```
PLANNING → SIGNING → DECORATING → TRAINING → SOFT_OPENING → OPENED → CLOSED
```
- 必须按顺序推进，不允许跨阶段
- 每次推进记录时间戳
- 关键节点需审批（见 BR-502）

### BR-502 · 门店状态变更审批要求
| 变更 | 是否需审批 | 审批人 |
|------|----------|-------|
| `SIGNING → DECORATING` | ✅ | 财务（确认首款） |
| `SOFT_OPENING → OPENED` | ✅ | 运营主管（验收） |
| `* → CLOSED` | ✅ | 运营主管 + 财务 |
| 其他 | ❌ | 直接推进 |

### BR-503 · 门店不可物理删除
只能软删除（`status = CLOSED` + `deletedAt` 标记）。历史合同、交易记录保留。

### BR-504 · 门店地理位置必填
`latitude` 和 `longitude` 为必填。如地址未能自动解析，需手动确认坐标。

### BR-505 · 门店每日数据唯一性
`(storeId, businessDate)` 为唯一键。同日重复录入视为更新，保留历史版本。

### BR-506 · 数据源优先级
多渠道录入时，主数据取以下优先级最高的：
```
API > EMAIL > AI_OCR > MANUAL
```
所有数据源保留原始记录，便于审计。

### BR-507 · 门店数据异常检测
自动标记为"异常"的条件（任一满足）：
- 营业额同比 > 50% 波动
- 订单数为 0 但营业额 > 0
- 客单价 > 上月平均 3 倍 或 < 1/3
- 营业时长与营业额极度不匹配

异常记录自动：
- 状态标记 `ANOMALY`
- 通知运营 + 加盟商
- 要求人工核对

### BR-508 · AI 识别数据的人工核对
通过 `AI_OCR` 录入的数据：
- `ocrConfidence < 0.8` → 强制人工核对
- 金额字段始终要求人工确认
- 修改过的字段标记 `aiEditedFields`

## 六、合同 / 审批（BR-6XX）

### BR-601 · 合同状态流转
```
DRAFT → APPROVING → SIGNED → EXECUTING → EXPIRED（终态）
                │              │
                └─ 驳回回 DRAFT └─ TERMINATED（终态）
```

### BR-602 · 合同必填字段
创建合同必填：
- 合同编号（自动生成或手工）
- 甲方、乙方
- 金额 + 币种
- 有效期起止
- 关联招商项目
- 至少一个关联门店

### BR-603 · 合同金额不可由 AI 修改
合同金额变更必须走人工审批流，`modify_contract_amount` 永远在 AI 黑名单。

### BR-604 · 审批超时升级
审批任务超过 48 小时未处理：
- 自动通知上级
- 再超 24 小时自动通知超管
- 支持配置超时时长

### BR-605 · 审批节点可加签/转交
- 加签：追加一个审批人
- 转交：转给其他人，自己不再审
- 所有动作记录审计

### BR-606 · 合同到期预警
自动通知（可配置）：
- 提前 90 天：通知相关销售
- 提前 60 天：通知加盟商
- 提前 30 天：通知加盟商 + 运营主管
- 提前 7 天：每日通知

### BR-607 · 合同软删除
历史合同不可物理删除。可标记 `TERMINATED`，审计保留。

## 七、财务（BR-7XX）

### BR-701 · 回款金额校验
`paymentAmount` 不能超过 `contractAmount - alreadyPaid`。

### BR-702 · 大额回款凭证
单笔回款 > ¥10,000 必须上传转账凭证。

### BR-703 · 分期计划校验
如选择分期，所有分期金额之和必须 = 合同总额（误差 ≤ 1 分）。

### BR-704 · 保证金退还
保证金退还申请必须：
- 金额 ≤ 已缴纳总额 − 已扣除金额
- 超管审批
- 退款凭证上传

### BR-705 · 违约扣款
从保证金扣款必须：
- 运营主管 + 财务双审批
- 填写扣款原因
- 通知加盟商

## 八、营销 / 内容（BR-8XX）

### BR-801 · 文章发布审核
普通内容运营发布 → `PENDING` 需审核。
超管 / 运营主管发布 → 直接 `PUBLISHED`（可配置）。

### BR-802 · 文章下架
已发布的文章：
- 运营可直接下架（状态改 `ARCHIVED`）
- 不可物理删除

### BR-803 · 小程序首页 Banner 数量
同时展示的 Banner ≤ 5 个。超出需排期或替换。

### BR-804 · Banner 跳转校验
Banner 跳转目标必须是系统内合法页面或白名单 H5 域名。

### BR-805 · 活动报名限制
- 活动有 `maxParticipants` 时，超额报名自动进候补
- 活动结束前 1 小时停止报名

## 九、小程序（BR-9XX）

### BR-901 · 留资频率限制
- 同手机号 24 小时最多 3 次留资
- 同 IP 1 小时最多 10 次
- 频繁提交触发滑动验证

### BR-902 · 留资必填字段
默认必填：姓名、手机、意向城市。其他字段由运营在 M10.2 配置。

### BR-903 · 留资进线索池规则
每次留资创建 1 条线索（除非 BR-201 去重），默认状态 `NEW`，未分配。

### BR-904 · 小程序用户的加盟商绑定
小程序用户成为加盟商后：
- 创建 `Merchant` 记录
- `User.roles` 追加 `MERCHANT_OWNER`
- 登录后可切换"C 端视图 / 加盟商视图"

## 十、数据看板 / 导出（BR-10XX）

### BR-1001 · 数据时效
```
实时（< 1 分钟）：待办、新增线索数、在线用户
准实时（< 1 小时）：当日业绩、漏斗
T+1（每日 1 点）：月度统计、趋势图
```

### BR-1002 · 导出数据量分级
- < 1 万行：同步下载
- 1-10 万行：异步任务 + 下载中心
- > 10 万行：异步任务 + 分片下载
- 下载链接有效期：7 天

### BR-1003 · 导出权限校验
导出操作的数据范围严格等于当前用户的数据权限。导出内容必须带水印/用户 ID，防泄露。

### BR-1004 · 看板数据范围
看板数据自动按用户 `dataScope` 过滤：
- `ALL`：全公司
- `DEPARTMENT`：本部门及下级
- `SELF`：自己

## 十一、AI 助手（BR-11XX）

### BR-1101 · AI 权限继承
AI 调用任何工具时，数据访问和操作能力**严格等于当前登录用户的权限**。
用户不能做的，AI 替用户也不能做。

### BR-1102 · 硬黑名单不可绕过
`HARD_BANNED_ACTIONS` 清单中的操作，即使用户有权限，AI 也不能执行。详见 [ai-security.md](./ai-security.md)。

### BR-1103 · 写入操作必须确认
所有 `requireConfirmation = true` 的工具：
- 调用时不立即执行
- 生成 `ActionProposal` 写入 DB，状态 `PENDING`
- 前端弹窗展示
- 用户确认后才执行
- 执行前再次权限校验

### BR-1104 · 操作确认超时
- LOW / MEDIUM：10 分钟
- HIGH：5 分钟
- 超时后 `PENDING → EXPIRED`，需重新发起

### BR-1105 · 配额熔断
- 达到 80% → 预警
- 达到 100% → 当日停用
- 次日自然恢复
- 管理员可紧急解锁（需审计）

### BR-1106 · API Key 加密
AI Provider 的 API Key 使用 AES-256-GCM 加密存储，加密主密钥从环境变量读取，不进代码仓库。

### BR-1107 · AI 审计日志
每一次工具调用写入 `AIActionLog`：
- 谁（userId）
- 何时
- 什么工具
- 什么参数
- 结果（或失败原因）
- IP / UA
**不可删除、不可修改。**

### BR-1108 · HIGH 风险操作二次保护
HIGH 风险操作需：
- 确认弹窗输入"确认"二字
- 自动通知上级
- 审计日志额外标记

### BR-1109 · AI 对话历史保留
默认保留 90 天。用户可手动删除（会话删除，但 `AIActionLog` 不删）。

### BR-1110 · AI Key 选择优先级
```
用户开启"个人优先" && 绑定了个人 Key → 用个人 Key
否则用全局默认 Key
全局也没有 → 报错"AI 未配置"
```

### BR-1111 · AI 响应数据的真实性保证
AI 回答数据必须基于工具调用结果，禁止基于"训练记忆"编造。
System Prompt 中必须包含："不确定时问用户，不要猜测"。

## 十二、通用 / 技术（BR-12XX）

### BR-1201 · 软删除为默认
所有业务表默认软删除（`deletedAt` 字段）。查询默认过滤已删除。
超管有"回收站"入口，30 天内可恢复。

### BR-1202 · 审计日志全量留痕
以下操作必须写 `AuditLog`：
- 所有创建/更新/删除
- 登录/登出
- 权限变更
- 数据导出
- 关键业务动作（审批、分配、状态变更）

### BR-1203 · 多租户字段预留
所有业务表预留 `tenantId` 字段（MVP 固定值 `default`）。查询层预留租户过滤钩子。

### BR-1204 · 时间存储
所有时间字段用 UTC 存储。前端按用户时区展示（默认 `Asia/Shanghai`）。

### BR-1205 · 金额存储
金额用 `Decimal(18, 2)` 或字符串形式传输。禁止 Float。

### BR-1206 · 幂等键
关键写入接口（支付、创建合同、分配线索）要求传幂等键（`Idempotency-Key` header）。

### BR-1207 · 文件上传
- 最大 50MB（图片 10MB、视频 50MB、文档 20MB）
- 白名单后缀
- 上传前校验 MIME
- 通过预签名 URL 直传存储（视频）

### BR-1208 · 密码与 Key 不打印
密码、API Key、Token 等敏感字段不出现在：
- 日志
- 错误消息
- 接口响应
- 审计日志

## 规则变更管理

### 新增规则
在对应模块下顺延编号，更新至本文档顶部编号规则说明。

### 修改规则
保留原规则编号，记录变更历史：
```
### BR-202 · 线索状态机【v1.1 2026-06-01】
[新内容]

变更历史：
- v1.0 2026-05-10：初版
- v1.1 2026-06-01：新增 WAITLISTED 中间态
```

### 废弃规则
不删除，改为：
```
### BR-XXX · [规则名]【已废弃 2026-XX-XX】
~~[原内容]~~

废弃原因：...
替代规则：BR-YYY
```

## 引用约定

### 代码中引用
```typescript
// BR-202 线索状态机
if (lead.status === LeadStatus.INVALID) {
  throw new BadRequestException('INVALID 为终态，不可流转');
}
```

### 文档中引用
`详见 [BR-202](./business-rules.md#br-202-线索状态机)`

### Commit 消息中引用
```
feat(lead): 实现线索状态流转 BR-202, BR-203

- 新增状态校验
- 新增自动回公海定时任务 BR-204
```
