# 🗺️ Irys 完整页面结构树

> **文档版本**：v1.0.0
> **最后更新**：2026-05-10
> **用途**：让你一眼看清楚整个系统有哪些页面、怎么嵌套、每个页面要做什么
>
> 📌 **使用说明**：
> 1. 做前端时按这里的路由配置
> 2. 做后台时知道每个页面要哪些 API
> 3. 估工时：**每个 🟢 简单页面 ≈ 0.5 天，🟡 中等 ≈ 1 天，🔴 复杂 ≈ 2-3 天**

---

## 📊 页面总览速览

```
Irys 系统 = 3 个端 + 共 ~92 个页面

┌─────────────────────────────────────────────┐
│  1️⃣  后台管理端 (apps/admin)    ~60 个页面   │
│      面向:内部员工 + 加盟商                  │
│      技术:Vue 3 + Element Plus               │
├─────────────────────────────────────────────┤
│  2️⃣  招商小程序 (apps/mini)     ~15 个页面   │
│      面向:C 端潜在加盟客户                   │
│      技术:uni-app + 微信小程序               │
├─────────────────────────────────────────────┤
│  3️⃣  加盟商移动端 (可选,MVP 不做)            │
│      暂时复用后台管理端(按角色隔离)           │
└─────────────────────────────────────────────┘

难度分布:
🟢 简单列表/表单页:约 50 个
🟡 中等(含筛选/图表/状态流转):约 30 个
🔴 复杂(审批流/AI/地图/多 Tab):约 12 个
```

---

## 🎯 难度图例说明

| 图例 | 难度 | 说明 | 预计工时 |
|------|------|------|---------|
| 🟢 | 简单 | 基础列表 / 表单 / 详情 | 0.5 天 |
| 🟡 | 中等 | 含筛选、多状态、权限、状态机 | 1 天 |
| 🔴 | 复杂 | 审批流 / 富文本 / AI / 地图 / 拖拽 | 2-3 天 |
| ⭐ | 重要 | 核心功能,必须做好 |
| 🔒 | 权限敏感 | 需特殊权限控制 |

# 📌 页面开发技巧(给小白)

## ✅ 做页面的标准顺序

1. **先做静态页面(Mock 数据)**
   - 用假数据把界面做出来
   - 验证 UI 正确

2. **再对接接口**
   - 替换假数据为真实 API

3. **最后加权限和边界**
   - 权限控制
   - 错误处理
   - Loading 状态
   - 空状态

## ⚠️ 小白常踩的 5 个坑

### 坑 1:一次做整个页面
❌ "我要做线索详情页,有 5 个 Tab"
✅ "我先做基本信息 Tab,跑通再做下一个"

### 坑 2:忽略 Loading/空/错误状态
每个数据展示区都要有这 3 种状态:
- 加载中(骨架屏/loading)
- 空数据(插图 + 文字)
- 错误(错误图 + 重试按钮)

### 坑 3:权限控制做在前端
**前端权限只是 UI 显示/隐藏,后端必须再校验一次!**

### 坑 4:表单没做校验
```typescript
// ❌ 不做校验
<el-input v-model="phone" />

// ✅ 做校验
<el-form-item
  prop="phone"
  :rules="[
    { required: true, message: '手机号必填' },
    { pattern: /^1\d{10}$/, message: '格式错误' }
  ]"
>
  <el-input v-model="phone" />
</el-form-item>
```

### 坑 5:按钮不做 Loading
```typescript
// ❌ 点击就触发,重复点击会发多次请求
<el-button @click="submit">提交</el-button>

// ✅ 提交中禁用
<el-button :loading="submitting" @click="submit">提交</el-button>
```

1. **一次只做一个页面,一个页面只做一个 Tab**
2. **先做静态再对接接口,先做数据再做权限**
3. **Loading / 空 / 错误三态,每个页面必有**
