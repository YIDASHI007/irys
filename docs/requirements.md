## 1. 产品定位

### 1.1 一句话定义

**一个让企业集中管理"人员、客户、招商、加盟商、门店、合同、财务、内容、数据"的中台系统，内置 AI 智能助手，对外通过招商小程序、H5 等触点承接流量。**

### 1.2 产品特色

- **后台驱动** — 所有对外内容由后台配置，小程序实时生效
- **AI 原生** — 内置 AI 助手，支持数据问答 + 操作协助
- **RBAC 完整** — 组织 / 角色 / 权限 / 数据权限四层模型
- **多端统一** — 后台 PC + 招商小程序 + 加盟商端共享同一后端
- **扩展友好** — 预留多租户、多品牌、电子签、支付等扩展点

### 1.3 不是什么

- ❌ 不是 ERP（不做进销存、生产、仓储）
- ❌ 不是 HR 系统（不做考勤、薪酬、绩效）
- ❌ 不是电商平台（不做 C 端购买、购物车）
- ❌ 不是 BI 工具（看板够用即可，不做自助分析）

## 5. 模块详情

### 🧩 M1 账号与权限中心

#### M1.1 组织架构
- 树形组织（集团 → 分公司 → 部门 → 小组，最多 6 级）
- 字段：名称、编码、负责人、联系电话、启停用
- 调整员工归属时保留历史（OrgAssignmentHistory）

#### M1.2 员工账号
- 新增/编辑/禁用/离职
- 字段：姓名、工号、手机、邮箱、所属组织、岗位、角色
- 批量导入（Excel 模板）
- 重置密码 / 首次登录强制改密
- 登录日志

#### M1.3 角色与权限（核心）
**三层权限模型**：
1. **菜单权限** — 能看到哪些页面
2. **按钮权限** — 页面内能点哪些按钮
3. **数据权限** — 能看哪些数据范围
   - `ALL` / `DEPARTMENT` / `SELF` / `CUSTOM`

**内置角色模板**：SUPER_ADMIN / OPS_MANAGER / SALES / FINANCE / REVIEWER / CONTENT_EDITOR / MERCHANT_OWNER

用户可基于模板扩展自定义角色。

#### M1.4 字典管理
- 系统字典（性别、证件类型、行业）
- 业务字典（线索来源、加盟商等级、门店类型…）
- 支持多级字典

#### M1.5 登录与安全
- 手机号 + 密码
- 手机号 + 短信验证码
- 登录失败次数锁定（5 次锁 15 分钟）
- 异地登录邮件/短信提醒
- JWT + Refresh Token 双 Token
- 扫码登录（企业微信，二期）

### 🧩 M3 CRM 客户中心

#### M3.1 线索管理
**字段**：姓名、手机（唯一）、城市、意向品牌、预算、来源、状态、归属销售、最后跟进时间

**来源**：小程序留资 / 官网留资 / 电话咨询 / 展会 / 转介绍 / 手工录入

**状态机**（详见 [business-rules.md](./business-rules.md)）：
```
NEW → CONTACTED → INTENTIONAL → CONVERTED
            ↓             ↓
         INVALID       INVALID
```

**功能点**：
- 线索查重（手机号去重）
- 线索分配：手动 / 规则（按地区、按品牌）
- 公海池 ↔ 私海
- 跟进提醒（下次跟进时间）
- 超时回收（N 天未跟进自动回公海，默认 15 天）
- 批量操作

#### M3.2 客户（已转化）
- 客户档案、联系人、标签
- 客户画像（来源、历史跟进、意向度）

#### M3.3 联系人
- 一个客户多个联系人
- 主联系人标记

#### M3.4 跟进记录
- 类型：电话 / 面谈 / 微信 / 现场考察 / 签约
- 支持文字 / 图片 / 语音 / 定位 / 附件
- 时间线视图

### 🧩 M6 门店管理

#### M6.1 门店档案
- 名称、编号、所属加盟商/品牌/项目
- 地址：省市区 + 详细 + **经纬度**
- 面积、业态、联系电话、营业时间
- 类型：旗舰店 / 标准店 / 社区店

#### M6.2 门店生命周期
```
PLANNING → SIGNING → DECORATING → TRAINING → SOFT_OPENING → OPENED → CLOSED
```
- 每阶段记录时间节点
- 关键节点需审批（开业验收）

#### M6.3 门店任务（达人探店整合）
- 门店任务列表
- 关联打卡、素材审核
- 完整状态机见 [business-rules.md](./business-rules.md)

#### M6.4 门店地图
- 全国门店分布地图
- 按品牌/状态筛选
- 热力图展示招商密度

#### M6.5 门店经营数据采集 ⭐
**多渠道录入**（应对"POS 无 API"）：
1. **官方 API**（有则优先）
2. **邮件附件自动解析**（定时导出 CSV → 邮箱 → 系统抓取）
3. **浏览器插件一键抓取**（轻量 RPA）
4. **AI 图片识别** → **独立模块 M15 AI OCR 数据录入** ⚠️ **仅 SUPER_ADMIN 可用**
5. **手工表单录入**（兜底）

**核心字段**：营业日期、总营业额、订单数、客流量、客单价、支付方式分布

**流程**：
```
员工上传截图/自动获取数据
    → 通过 M15 OCR 识别 / 解析 → 预填表单
    → 异常检测（同比波动 > 50% 打标）
    → 人工核对确认
    → 入库 + 审计日志
```

**反作弊**：图片 hash 去重、EXIF 时间戳、异常波动告警、抽查机制

**详细 OCR 能力设计见 [ai-ocr-module.md](./ai-ocr-module.md)**

### 🧩 M14 AI 智能助手 ⭐

> **完整安全方案见 [ai-security.md](./ai-security.md)**
> **完整工具清单见 [ai-tools-registry.md](./ai-tools-registry.md)**

#### M14.1 AI 配置管理（混合 Key 模式）

**核心规则**：优先级链
```
用户 AI 请求
  → 优先级 1：用户个人 Key（若已绑定且偏好"个人优先"）
  → 优先级 2：全局默认 Key（若已配置）
  → 否则：报错"AI 功能未配置"
```

**功能点**：
- 管理员端
  - [ ] 配置全局默认 API Key（AES-256-GCM 加密）
  - [ ] 设置全局配额（每日/每月 token 上限）
  - [ ] 允许/禁止用户绑定个人 Key 开关
  - [ ] 全局配额消耗排行榜
  - [ ] 每用户 AI 使用情况
- 用户端
  - [ ] 查看当前使用的 Key 类型
  - [ ] 绑定/更换/解绑个人 Key
  - [ ] 本月消耗统计
  - [ ] 偏好设置
    - 优先用我的个人 Key
    - 优先用公司 Key
    - 公司 Key 超配额时自动用个人 Key

**MVP 只支持 Kimi（月之暗面）**，但代码结构按多 Provider 抽象，后续可加 DeepSeek / 通义 / 豆包。

#### M14.2 对话功能
- 会话管理（新建/删除/重命名/历史检索）
- 流式消息（SSE）
- Markdown + 代码高亮 + 表格 + 图表渲染
- 停止生成 / 重新生成
- 上下文窗口管理（超限自动摘要）

#### M14.3 数据问答（基于真实数据）

AI 通过 **Function Calling** 调用预定义的查询工具获取数据，**严格按当前用户权限过滤**。

示例：
> 用户："本月哪个销售签约最多？"
> AI 理解 → 调用 `get_sales_ranking(period=this_month, metric=signed)` → 带着用户 ID 走权限过滤 → 返回数据 → AI 用自然语言总结

MVP 查询工具清单：**15 个**（详见 ai-tools-registry.md）

#### M14.4 操作助手（带确认）

AI 可以协助用户完成写入操作，但**必须满足以下条件**：
1. 用户本人有该操作权限
2. 操作不在硬黑名单内
3. 用户在弹窗中点击"确认"

**流程**：
```
用户："把张三的线索转给李四"
    ↓
AI 调用 assign_lead() → 服务端不立即执行
    ↓
服务端生成操作预览 → 前端弹窗
    ↓
用户点击"确认" → 回传 actionId
    ↓
服务端再次校验权限 → 执行 → 审计日志
    ↓
AI 告知结果："已成功转移 23 条线索"
```

**两级风险弹窗**：
- `LOW/MEDIUM` — 普通确认弹窗
- `HIGH` — 确认 + 输入"确认"文字 + 通知上级

MVP 写入工具清单：**15 个**（详见 ai-tools-registry.md）

#### M14.5 安全与审计
- API Key AES-256-GCM 加密存储
- 三层权限校验（黑名单 / 角色 / 数据）
- AI 操作全量审计（独立表 `AIActionLog`）
- 异常行为检测（频次、操作类型）
- Prompt 注入防护
- 敏感字段脱敏开关（预留）

#### M14.6 配额与成本
- Token 计数（input + output + cached）
- 每日/每月配额熔断
- 成本统计看板（公司级 + 个人级）
- 超限预警（短信/邮件）

### 🧩 M15 AI OCR 数据录入 ⭐

> **完整设计见 [ai-ocr-module.md](./ai-ocr-module.md)**（独立 PRD）
>
> ⚠️ **重要安全限制**：此模块**仅 `SUPER_ADMIN` 角色可用**。硬编码限制，不可通过权限配置覆盖。
>
> 理由：AI OCR 是"AI 直接写入业务数据"的能力，必须由最高权限把关。

#### M15.1 定位

独立的 AI 视觉能力模块，与 M14（对话型 AI）并列，共同构成 Irys 的 AI 能力矩阵：
- **M14 AI 助手** — 对话、问答、工具调用（视觉弱）
- **M15 AI OCR** — 图片识别、字段解析、结构化入库（视觉专用）

两者共享 Kimi K2.6 多模态 API（决策 D15-5）。

#### M15.2 核心功能

| 子模块 | 功能 |
|--------|------|
| M15.1 | 场景注册（MVP 仅门店数据，框架通用预留合同/身份证/小票等） |
| M15.2 | 图片上传与存储（OSS 直传、hash 去重） |
| M15.3 | OCR 识别流程（Kimi 多模态调用） |
| M15.4 | 字段解析与校验 |
| M15.5 | 人工核对界面（**强制**，决策 D15-6） |
| M15.6 | 反作弊机制（hash 去重、EXIF 校验） |
| M15.7 | 异常检测（业务规则联动） |
| M15.8 | 成本与配额监控 |

#### M15.3 六项核心决策

| 编号 | 决策 |
|------|------|
| D15-1 | 框架通用，MVP 只跑门店数据 |
| D15-2 | 10-15 个字段（营业额、订单数、客流、客单价、分时段、支付方式等） |
| D15-3 | **仅 SUPER_ADMIN 可用** ⚠️ |
| D15-4 | 单店单日录入 |
| D15-5 | 复用 Kimi 多模态（不引入第二家） |
| D15-6 | 永远人工核对（置信度再高也要确认） |

#### M15.4 数据流

```
SUPER_ADMIN 进入录入页
  → 选择门店 + 日期
    → 上传截图（1-5 张，带 hash 去重）
      → Kimi K2.6 多模态识别 → 返回结构化 JSON + 置信度
        → 前端并列显示：[原图] vs [识别结果表单]
          → 低置信字段红色高亮
            → 人工逐字段核对 + 修改（留痕）
              → 业务异常检测（联动 BR-507）
                → 入库 StoreDailyData（标记 source=AI_OCR）
                  → 写入完整审计日志（独立 AIOcrAuditLog 表）
```

#### M15.5 两个新增 AI Tool（详见 ai-tools-registry.md）

- **T31 `ocr_parse_store_data`** — 调用 AI 视觉识别门店截图
- **T32 `submit_ocr_reviewed_data`** — 核对后提交入库

两个 Tool 均标记 `requiredRoles: [SUPER_ADMIN]`。

#### M15.6 未来扩展

- v2：建立 "OCR 操作员" 子角色，允许授权开放

## 7. 非功能性需求

### 7.1 性能
- 首屏加载 < 2s
- 接口平均响应 < 500ms
- 支持同时在线 500 用户（MVP）
- AI 流式首字节 < 2s

### 7.2 安全
- 密码 bcrypt 加密
- HTTPS 全站
- JWT + Refresh Token
- SQL 注入 / XSS / CSRF 防护
- 敏感字段脱敏（身份证、银行卡）
- 登录失败限流
- 操作审计完整留存
- **AI API Key AES-256-GCM 加密**

### 7.3 可用性
- 核心接口可用性 ≥ 99.5%
- 每日数据库备份，保留 30 天
- 关键操作防误删（软删除 + 回收站）

### 7.4 合规
- 个保法：数据最小化收集、支持删除请求
- 小程序类目合规（招商加盟需类目报备）
- 数据出境明确区域

### 7.5 扩展性
- 多租户预留（`tenant_id` 字段）
- 多品牌隔离（`brand_id` 字段）
- 国际化字段结构预留

### 7.6 可观测性
- 结构化日志（pino）
- 请求追踪（traceId）
- 错误上报（Sentry）
- 健康检查 `/health`
